# admin-bootstrap Specification

## Purpose

讓全新或不含管理員記錄的資料庫可透過公開網頁建立第一位管理員，並在管理員存在後封鎖初始化功能，確保系統進入正常使用流程。

## Requirements

### Requirement: 公開初始化狀態
系統 SHALL 根據持久化資料中是否存在 `ADMIN` 記錄，向未認證的網站用戶端提供目前是否需要管理員初始化的狀態。

#### Scenario: 資料庫沒有管理員
- **GIVEN** 資料庫不存在任何角色為 `ADMIN` 的使用者記錄
- **WHEN** 用戶端查詢初始化狀態
- **THEN** 系統回覆需要初始化

#### Scenario: 資料庫已有管理員
- **GIVEN** 資料庫至少存在一筆角色為 `ADMIN` 的使用者記錄
- **WHEN** 用戶端查詢初始化狀態
- **THEN** 系統回覆不需要初始化

### Requirement: 無管理員時強制導向初始化頁面
當資料庫沒有 `ADMIN` 記錄時，網站 SHALL 將所有一般頁面導向公開的新增管理員頁面，且一般註冊與登入流程暫不可使用。

#### Scenario: 訪客開啟一般頁面
- **GIVEN** 資料庫沒有 `ADMIN` 記錄
- **WHEN** 訪客開啟登入、註冊、首頁或其他一般網站路由
- **THEN** 網站將訪客導向新增管理員頁面

#### Scenario: 訪客開啟初始化頁面
- **GIVEN** 資料庫沒有 `ADMIN` 記錄
- **WHEN** 訪客開啟新增管理員頁面
- **THEN** 網站顯示使用者名稱、密碼及確認密碼欄位

### Requirement: 建立第一位管理員
當資料庫沒有 `ADMIN` 記錄時，系統 SHALL 允許任何公開網路訪客提交有效的使用者名稱與密碼，並建立角色固定為 `ADMIN` 的第一位管理員。

#### Scenario: 成功建立管理員
- **GIVEN** 資料庫沒有 `ADMIN` 記錄
- **WHEN** 訪客提交尚未使用且格式有效的使用者名稱、合格密碼及相符的確認密碼
- **THEN** 系統建立角色為 `ADMIN` 的帳號
- **AND** 系統不保存可還原的明文密碼
- **AND** 系統引導訪客前往登入頁面

#### Scenario: 初始化資料無效
- **GIVEN** 資料庫沒有 `ADMIN` 記錄
- **WHEN** 訪客提交重複或格式無效的使用者名稱、不合格密碼或不相符的確認密碼
- **THEN** 系統拒絕建立管理員並提供可修正的錯誤訊息

### Requirement: 管理員初始化具原子性
系統 MUST 在持久化交易中重新檢查 `ADMIN` 是否存在，使同時送達的初始化請求至多只有一個能建立第一位管理員。

#### Scenario: 兩個初始化請求同時送達
- **GIVEN** 資料庫起初沒有 `ADMIN` 記錄
- **WHEN** 兩個有效的新增管理員請求同時送達
- **THEN** 系統只允許其中一個請求建立 `ADMIN`
- **AND** 另一個請求收到初始化已完成的衝突回應

### Requirement: 管理員存在後封鎖初始化
只要資料庫存在 `ADMIN` 記錄，系統 MUST 禁止使用新增管理員頁面及其寫入 API；此限制 MUST 由後端執行，不得只依賴前端路由。

#### Scenario: 開啟已停用的初始化頁面
- **GIVEN** 資料庫已有 `ADMIN` 記錄
- **WHEN** 訪客嘗試開啟新增管理員頁面
- **THEN** 網站將訪客導向登入頁面

#### Scenario: 直接呼叫已停用的初始化 API
- **GIVEN** 資料庫已有 `ADMIN` 記錄
- **WHEN** 用戶端直接提交新增管理員 API 請求
- **THEN** 後端拒絕請求且不建立或修改任何使用者記錄

### Requirement: 初始化完成後開放一般註冊
第一位管理員建立完成後，系統 SHALL 恢復一般登入流程，並持續允許訪客自行註冊角色為 `USER` 的帳號。

#### Scenario: 初始化後註冊一般使用者
- **GIVEN** 資料庫已有 `ADMIN` 記錄
- **WHEN** 訪客開啟註冊頁面
- **THEN** 網站顯示一般使用者註冊介面
