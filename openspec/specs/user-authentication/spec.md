# user-authentication Specification

## Purpose

提供一般使用者可持續使用的安全帳號生命週期，涵蓋自行註冊、帳密登入、JWT 驗證、登出，以及在登入後辨識目前使用者。

## Requirements

### Requirement: 一般使用者自行註冊
當系統已存在管理員時，系統 SHALL 允許未登入訪客使用唯一的使用者名稱與密碼註冊一般使用者帳號，且新帳號的角色固定為 `USER`。

#### Scenario: 成功註冊一般使用者
- **GIVEN** 系統已有至少一筆 `ADMIN` 記錄
- **WHEN** 訪客提交尚未使用且格式有效的使用者名稱及合格密碼
- **THEN** 系統建立角色為 `USER` 的帳號
- **AND** 系統不保存可還原的明文密碼

#### Scenario: 使用者名稱重複
- **GIVEN** 系統已有相同正規化使用者名稱的帳號
- **WHEN** 訪客提交註冊資料
- **THEN** 系統拒絕註冊並回傳不揭露其他帳號資料的衝突錯誤

#### Scenario: 註冊資料格式無效
- **WHEN** 訪客提交空白或不符合長度及格式規則的使用者名稱或密碼
- **THEN** 系統拒絕註冊並指出可修正的欄位驗證錯誤

### Requirement: 使用者帳密登入
系統 SHALL 驗證已啟用帳號的使用者名稱與密碼，成功時建立具有限時效力的 JWT 認證工作階段，失敗時不得透露帳號是否存在。

#### Scenario: 登入成功
- **GIVEN** 使用者帳號已啟用且密碼正確
- **WHEN** 使用者提交登入資料
- **THEN** 系統建立含使用者識別、使用者名稱、角色與到期時間的已簽署 JWT 工作階段

#### Scenario: 登入資料錯誤
- **WHEN** 使用者提交不存在的使用者名稱或錯誤密碼
- **THEN** 系統拒絕登入並回傳一致的帳號或密碼錯誤訊息

#### Scenario: 帳號未啟用
- **GIVEN** 使用者帳號已停用
- **WHEN** 使用者提交正確的使用者名稱與密碼
- **THEN** 系統拒絕建立認證工作階段

### Requirement: JWT 保護 API
系統 MUST 僅允許持有有效、未到期且簽章正確 JWT 的使用者存取受保護 API，並依 JWT 代表的角色執行授權。

#### Scenario: 有效 JWT
- **WHEN** 用戶端以有效 JWT 呼叫符合其角色權限的受保護 API
- **THEN** 系統接受該使用者身分並處理請求

#### Scenario: 缺少或無效 JWT
- **WHEN** 用戶端未提供 JWT，或提供已到期、遭竄改或簽章無效的 JWT
- **THEN** 系統拒絕請求並回傳未認證狀態

#### Scenario: 權限不足
- **GIVEN** JWT 有效但使用者角色不符合 API 權限
- **WHEN** 用戶端呼叫該 API
- **THEN** 系統拒絕請求並回傳禁止存取狀態

### Requirement: 顯示目前使用者名稱
系統 SHALL 提供目前已認證使用者資訊，且登入後的網站介面 SHALL 清楚顯示該使用者名稱。

#### Scenario: 載入已登入頁面
- **GIVEN** 使用者具有有效認證工作階段
- **WHEN** 網站載入或重新整理已登入頁面
- **THEN** 系統取得並顯示目前使用者名稱

#### Scenario: 工作階段已失效
- **GIVEN** 原有 JWT 已失效或到期
- **WHEN** 網站嘗試取得目前使用者資訊
- **THEN** 系統清除前端登入狀態並引導使用者重新登入

### Requirement: 使用者登出
系統 SHALL 允許已登入使用者結束瀏覽器中的認證工作階段，並在登出後停止以原工作階段呼叫受保護 API。

#### Scenario: 登出成功
- **GIVEN** 使用者目前已登入
- **WHEN** 使用者執行登出
- **THEN** 系統移除瀏覽器持有的認證憑證並導向登入頁面

### Requirement: 離線提供核心前端資產
註冊、登入與已登入頁面所需的核心前端程式、樣式及圖示 SHALL 由應用程式本身提供，不得依賴外部 CDN 才能運作。

#### Scenario: 無法連線外部 CDN
- **WHEN** 使用者可連線至應用程式但無法連線至任何外部 CDN
- **THEN** 註冊、登入、登出與顯示使用者名稱的介面仍可完整運作
